# 质检流程（质检开启时才读）

> **什么时候读这份文件**：用户在当前任务中明确说「质检 / 严格质检 / 用机器视觉查 / 帮我检查 / 看看有没有问题」时。
> **默认状态下不读本文件**——主 `SKILL.md`「质检基准」已规定：看图与审核默认交给人，agent 只做机械项并附一份「请重点看这几点」清单。
> 本文件是**主 `SKILL.md` 的延伸**（原文整段搬来，规则以主文件为准；本文件只补充「怎么执行质检」）。

## 一、为什么 `read` 读图不可靠（用任何读图结论前先看这段）

用 `read` 读取本地图片做质检会与用户实际看到的成图不一致（`read` 自动降采样压缩，2048 级大图缩尺寸后小字号 Logo、手写体、结构细节糊化，易按训练先验脑补误判；且生成→去水印→落盘为异步流程，读到的可能是中途/缓存副本，与 Review 面板渲染版不同步）。
**更严重形态：`read` 可能返回完全不相干的另一张图片**，会直接诱导出“图没编辑/版式丢失”的错误定论。因此读图结论必须先交叉验证再出口。
**代价实证 **：`read` 裁剪图返回了不相干画面，诱导出"生成图缺 Logo"的误判，据此做了多余的 PIL 贴回修复——实际原图自带完整 Logo，贴回造成双熊重影返工。裁剪目视前先核对裁剪文件的尺寸、时间戳与来源路径以确认读到的确实是该文件本身；质检开启时另用视觉分析通道追问该裁剪文件的真实内容（问“这张图里有什么”），read 与视觉问答结论冲突时不得直接采信 read；质检默认关闭时改用来源核对 + 直接询问用户，**不为此调用机器视觉**。


## 二、质检开启时的三条流程
6. **独立视觉通道交叉验证（质检开启时的必经步骤；质检默认关闭时本条不执行，改按「质检开关」的单通道安全约束处理）**：要判定「是否原图未改 / 文案是否渲染 / 有无乱码」，先用**机器视觉通道**传本地路径做视觉分析（或把多张输出合成 `PIL` 拼图后一次分析），与 `read` 结论比对。裁决序列为**原图裁剪目视 + 机器视觉分析 + 用户观察**，三者冲突时以用户观察为准，`read` 单方结论不作数。**通道选择**：质检通道应选与生图厂商不同的一家，避免同源偏差；仅在主通道不可用或超时时回退。**能力边界**：机器视觉通道只作结构级判断（凸/凹、有/无、文案有无乱码），**毫米级计数与小字不得由它单独定论**，须回到原图裁剪目视。辅助的客观信号：输出文件尺寸是否符合目标比例、与参考图的感知哈希距离（距离极小才可能是原图未改）。**「没画出来」与「画了但看不清」必须分开判**：机器视觉通道回答「无法确认 / 未展示 / 被遮挡 / 角度遮挡」时，**不得记为「信息不足」直接放过**——这句话同时覆盖两种性质完全不同的缺陷：① 该元素根本没出现在画面里（模型省略，整件缺失）；② 元素存在但角度/尺寸导致不可辨（构图朝向问题，元素完整）。处理：先按元素类型追问「完全没有出现，还是出现了但看不清」并要求二选一回答，再决定是重生成还是只调朝向。漏检典型：配件全家福的凹头母座整端缺失，视觉通道报「无法确认设备端接口形态」，被当成信息不足放行，实为整件缺失。
8. **小部件结构复检（仅质检开启时执行；默认关闭态不做）**：凡画面含配件接口、插头端头、金属插脚、按键刻字、Logo 文字等毫米级结构，**用户明确要求质检时**才从原图裁剪该区域放大后目视核对（质检开启时另加独立视觉通道交叉验证），禁止用整图缩略图/总览拼图代替（缩略后仅几像素，"看不见"会被误判为"没问题"）；独立通道对此类细节可能幻觉（曾把无插脚报成"3 根金属插脚"），与目视或用户观察冲突时以后者为准。**默认关闭态：不做裁剪目视，改为在交付清单里点名这类要素**（如「电源线两端形态 → 请重点看」），让人来判断。
9. **裁剪/对照图落盘与展示校验**：凡为质检、核对、交付而裁剪或合成的对照图（开关/接口放大、Logo 局部、透视区放大、总览拼图等），**必须先落盘到与展示通道同一目录**（文件名用 ASCII 英文）后再展示；**禁止跨目录拼 URL**（如把落在 A 目录的裁剪图按 B 目录的 URL 展示——服务只托管指定输出目录，跨目录必 404）。**每条对外 URL 展示前必须双校验**：存在性（核对磁盘路径）+ 可达性（HTTP 探测 200 且字节数与磁盘一致），先过校验再输出，不凭印象拼串。单次 `Test-Path` 拦不住「文件在磁盘但 URL 漏目录前缀」类拼串错误，必须有 HTTP 探测兜底。**SVG 破图根因**：若展示通道对 `.svg` 返回非 `image/svg+xml` 的 Content-Type，客户端渲染器会拒收 → 破图，且 HTTP 探测 200 照样通过（探测只验字节不验渲染）。**SVG 一律先转 PNG 再走白名单 URL 展示**：可用 Edge headless 渲染（`msedge.exe --headless --disable-gpu --screenshot="输出.png" --window-size=宽,高 "file:///源.svg"`，窗口尺寸按 viewBox 比例 ×2），转完用 PIL 可读回校验；SVG 源文件另行留存交付。
